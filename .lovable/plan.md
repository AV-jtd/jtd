# Чат по SKU/проекту + синхронизация с «Эфиром»

## Что уже есть (не трогаем схему БД)
- Каждый SKU и проект — это строка в `task_groups`, у которой уже есть `group_id` → чат `group_messages` (через `ProjectChat` / `useGroupMessages`).
- У проектов чат выведен во вкладке «Обсуждение». **У SKU чат в UI не выведен.**
- «Эфир» существует только в Комнате клиента (`ClientRoomCenter.tsx`) и строит события из задач клиента. Сообщения чата в него сейчас не попадают.
- STM-SKU **не связаны** с клиентом (`client_id` в модуле не используется); «Сеть» хранится как свободный текст `stm_meta.retailer`.

## Деливери

### 1. Чат по SKU (STM-матрица)
- В `StmExpandedRow.tsx` добавить кнопку-переключатель «Чат» (иконка `MessageSquare` в STM-акценте) рядом с кнопкой «Гантт».
- По клику — раскрывать встроенный `<ProjectChat groupId={group.id} embedded />` в нижней части раскрытой строки SKU. Бэкенд не меняем: `useGroupMessages(group.id)` работает сразу.
- Существующее поле-комментарий (`task_groups.description`) остаётся как есть — это «ТЗ/нюансы», отдельно от чата.

### 2. Вывод сообщений в «Эфир» Комнаты клиента
- Новый хук `useClientChatEvents(clientId)`:
  - грузит имя клиента;
  - находит SKU-группы, где `lower(stm_meta->>'retailer')` совпадает с `lower(client.name)` → помечает их `isNpd: true`;
  - находит проектные/CRM-группы клиента (как в `useClientTasks`) → обычный чат;
  - запрашивает последние `group_messages` по объединённому списку `group_id`, подтягивает профили авторов;
  - возвращает события `kind: "message"` c полями `isNpd`, `groupName`, `content`, `actorId`, `time`.
- `ActivityFeed` расширяем: принимает `chatEvents`, мержит их с событиями задач, сортирует по времени.
- Realtime: подписка `group_messages` уже инвалидирует чаты; добавим инвалидацию ключа нового хука при вставке сообщения.

### 3. Визуальная метка NPD + фильтр
- Событие NPD-чата: значок `MessageSquare` в STM-акцентном цвете + бейдж «NPD» и подпись названия SKU.
- Над лентой — переключатель-фильтр: «Все» / «Только NPD-чат» (и/или «Без чатов»). По умолчанию «Все».

## Важный нюанс доступа (RLS) — нужно решение
`group_messages` виден только участникам группы (`is_group_member`) или владельцу/админу. При создании SKU (`useCreateStmSku`) участники (`group_members`) не добавляются — владельцем считается создатель.

Последствие: **сообщения SKU-чата в «Эфире» и сам чат SKU увидит только создатель SKU (владелец) и админ**, а не вся команда.

Варианты (за рамками текущего плана, выберите один):
- **A. Быстро/как есть** — чат SKU виден владельцу и админу. Команда — позже.
- **B. Авто-участники** — при создании SKU или при первом открытии чата добавлять пользователей в `group_members` (потребуется правка `useCreateStmSku` и/или новая RLS-политика self-join). Больше работы, но чат виден команде.

Реализую пункты 1–3 сейчас в варианте **A** (без изменения прав). Если нужен вариант B — скажите, добавлю отдельным шагом.
