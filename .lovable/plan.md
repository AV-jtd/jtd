# Подключение JTD к Claude через MCP

## Зачем это нужно

Сейчас работа с JTD ограничена браузером/PWA/Telegram. Claude — ваш «мыслящий слой»: он умеет разбирать письма, документы, длинные цепочки решений. Но **у него нет доступа к вашим задачам, проектам, протоколам и клиентам**, поэтому каждый раз приходится копировать данные руками.

MCP (Model Context Protocol) — это открытый стандарт, который делает JTD «подключаемым приложением» внутри Claude. После настройки у вас появится:

**В Claude (Desktop и Web)**
- В меню «Connectors» → «Add custom connector» → вставляете URL → логинитесь своим аккаунтом JTD → всё, Claude видит ваши данные.
- Дальше можно просто писать: *«покажи мои просроченные задачи по Пятёрочке»*, *«создай задачу по итогам этой встречи»*, *«найди все протоколы по СТМ за квартал и сделай саммари»* — Claude сам вызывает нужные инструменты.

**Практические сценарии для АПХ Дороничи**
1. **Разбор входящих** — переслал письмо в Claude, он предложил структуру, одной командой создал задачи в JTD с привязкой к клиенту и дедлайнами.
2. **Weekly cross-functional review** — Claude вытягивает все просрочки/дрифт по проектам и готовит повестку встречи.
3. **Работа с протоколами** — Claude читает старые протоколы по теме и напоминает договорённости перед новой встречей.
4. **CRM-анализ** — *«по каким клиентам движения не было >30 дней?»* — Claude запрашивает данные через MCP и отвечает.

Ключевое: **Claude действует от вашего имени**, RLS работает как обычно — он видит только то, что видите вы; коллеги через свой Claude видят только своё.

## Что делаем

### 1. Инфраструктура OAuth (бэкенд)
Активируем OAuth 2.1 authorization server на вашем Supabase (`supabase--configure_oauth_server`). Это даёт Claude стандартный способ логиниться в JTD без ручных токенов и API-ключей.

### 2. Страница согласия (фронтенд)
Роут `/.lovable/oauth/consent` — экран «Claude просит доступ к вашему аккаунту JustTODOit. Разрешить?» с кнопками «Разрешить»/«Отклонить». Использует существующий Supabase-клиент. Логин через уже настроенный `/auth` (email/пароль + Google).

### 3. MCP-сервер (edge function)
Пакет `@lovable.dev/mcp-js` + Vite-плагин генерирует Supabase Edge Function `mcp`, которая:
- Валидирует OAuth-токен от Supabase Auth
- Выполняет каждый инструмент под ролью залогиненного пользователя (RLS сама фильтрует)
- Разворачивается по адресу `https://nvfioycpwyzwukvokwql.supabase.co/functions/v1/mcp`

### 4. Инструменты MVP (4 группы, ~15 штук)

**Задачи**
- `list_tasks` — фильтры: overdue / today / this_week / project_id / assignee_me / status
- `get_task` — детали, шаги, комментарии
- `create_task` — заголовок, дедлайн, проект, клиент, ответственный
- `complete_task` — закрыть задачу
- `update_task_deadline` — сдвинуть дедлайн (пишется в drift)

**Проекты**
- `list_projects` — с фильтром «активные/архив», тип (PMO/NPD/CRM/protocol)
- `get_project` — метрики: прогресс, просрочки, дрифт, ближайшие вехи

**Протоколы**
- `list_protocols` — фильтры: клиент, дата, тема, статус (draft/published)
- `get_protocol` — содержимое, повестка, связанные задачи, участники

**CRM-клиенты**
- `list_clients` — фильтры: территория, ранг, менеджер
- `get_client` — воронка, последние 30 дней активности, связанные задачи и протоколы

Каждый инструмент — отдельный файл в `src/lib/mcp/tools/`, с чёткими описаниями (Claude по ним понимает, когда что звать) и Zod-валидацией входа.

### 5. Инструкция пользователю
В `README` короткий раздел «Как подключить Claude»: URL + шаги в Claude Settings → Connectors.

## Технические детали

**Файлы**
- `src/lib/mcp/index.ts` — `defineMcp`, OAuth issuer, список инструментов
- `src/lib/mcp/tools/*.ts` — по одному файлу на инструмент
- `src/pages/OAuthConsent.tsx` + роут `/.lovable/oauth/consent` в `App.tsx`
- `vite.config.ts` — добавить `mcpPlugin()`
- `.lovable/mcp/manifest.json` — регенерируется автоматически

**OAuth issuer** — `https://nvfioycpwyzwukvokwql.supabase.co/auth/v1` (прямой Supabase, не lovable.cloud-прокси — иначе MCP-верификатор отклонит токен).

**Безопасность**
- Каждый tool делает `createClient(URL, ANON, { headers: { Authorization: Bearer ${ctx.getToken()} } })` — то есть все запросы идут под RLS пользователя.
- `SERVICE_ROLE_KEY` в MCP-коде не используется вообще.
- Токены не логируются и не возвращаются наружу.

**После деплоя**
- Автоматически: страница согласия, edge function `mcp`, OAuth endpoints Supabase.
- Вручную (пользователем в Claude): Settings → Connectors → Add custom → вставить `https://nvfioycpwyzwukvokwql.supabase.co/functions/v1/mcp` → пройти OAuth.

**Что НЕ входит в MVP** (можно добавить потом)
- Запись в протоколы/CRM (пока только чтение)
- Массовые операции (bulk delete/reassign)
- AI-функции JTD (Risk Radar и т.п.) — Claude сам умеет анализировать, дублировать не нужно
- Загрузка файлов через MCP
