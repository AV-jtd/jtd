# Этап 4 — Единый чат: TG ↔ MAX ↔ JTD (нативные группы + ChatOps)

## Идея в одной строке
Каждый проект JTD можно связать с группой в Telegram и/или MAX. Бот сидит в группе, всё, что пишут в группе, попадает в чат проекта JTD (и наоборот), а любая команда/задача из группы работает в контексте этого проекта без указания имени.

## 1. Модель данных (источник правды — `group_messages`)
- `task_groups.telegram_group_chat_id` (bigint, nullable, unique) — связь проект↔TG-группа.
- `task_groups.max_group_chat_id` (text, nullable, unique) — связь проект↔MAX-группа.
- `group_messages`: использовать существующий `source` (`web` | `telegram` | `max`); добавить `external_author` (имя автора, если он не сопоставлен с JTD-аккаунтом) и опц. `external_message_id` (для дедупликации/реплаев).
- `chat_link_tokens` (channel, code, group_id, created_by, expires_at 1ч, RLS по auth.uid()) — коды привязки. Можно переиспользовать паттерн `max_link_tokens`.

## 2. Привязка группы (workflow)
**Из JTD (Настройки проекта → новая секция «Каналы чата»):**
```text
[Подключить Telegram-группу]  →  код JTD-7F3A (живёт 1 час)
   Инструкция: добавьте бота @… в группу и отправьте там  /link JTD-7F3A
[Подключить MAX-группу]       →  аналогично
```
- Бот в группе получает `/link <код>` → валидирует код → пишет `telegram_group_chat_id` на проект → подтверждает в группе и в JTD.
- В секции после привязки: название группы, число участников, кнопка «Отвязать» (`/unlink` в группе тоже работает).

**Важно для TG:** для полного зеркалирования переписки у бота должен быть выключен Privacy Mode в BotFather (иначе бот видит только команды/упоминания/реплаи). Это вынесем в инструкцию подключения.
**Для MAX:** сначала короткая проверка, что бот MAX штатно работает в групповых чатах (получает `message_created` из группы) — TG это проверенный путь, MAX подтвердим API-вызовом.

## 3. Двунаправленное зеркалирование + подавление эха
Правило fan-out: сообщение доставляется во все привязанные каналы, **кроме канала-источника**.
```text
JTD (web)   → отправить в TG-группу + MAX-группу
TG-группа   → записать в group_messages (realtime в JTD) + отправить в MAX-группу
MAX-группа  → записать в group_messages + отправить в TG-группу
```
- Эхо не зацикливается: Telegram/MAX не присылают боту его же сообщения обратно.
- Идентичность: входящий автор из TG/MAX резолвится `from.id → profiles.telegram_user_id/max_user_id → JTD-пользователь`. Если не сопоставлен — сообщение всё равно отображается как `Имя (TG)` через `external_author`, с мягким приглашением привязать аккаунт.
- Личка бота остаётся для **персональных** уведомлений (назначено вам, дедлайн, упоминание) и команд 1:1 (`/my`, `/done`). Групповой разговор идёт в группу. Это устраняет «стену» из старого per-user fan-out для чата.

## 4. ChatOps — чат как рабочая поверхность
Внутри группы проекта контекст проекта известен, поэтому:
- **Естественный язык** → `aiBulkParse` создаёт задачу(и) сразу в этом проекте: `@Альберт подготовь КП к пятнице` → задача с ответственным и дедлайном, ответственный ищется среди участников проекта.
- После создания бот постит в чат компактную карточку `✅ Новая задача` (та же, что уходит в JTD), во все каналы.
- Команды (общее ядро, работают и в TG, и в MAX): `/new`, `/my`, `/tasks`, `/done N` (+ inline-кнопки `✅ N`), `/assign`. Все скоупятся на проект группы — без указания имени проекта.
- Задачи, созданные/закрытые в самом JTD, тоже постят карточку в привязанные группы (через тот же `send-chat-*`).

## 5. UI в JTD
- **Настройки проекта → «Каналы чата»**: подключить/отвязать TG и MAX, статус связи, число участников.
- **Панель чата проекта**: индикатор «единый чат» (иконки TG/MAX), у сообщений из мессенджеров — маленький бейдж канала рядом с автором.
- **Unified messenger (правый сайдбар)**: бейджи каналов на тредах проектов.

## 6. Этапность реализации
1. **Миграция БД**: колонки связей на `task_groups`, поля автора в `group_messages`, таблица кодов привязки + GRANT/RLS.
2. **Привязка**: `/link`/`/unlink` в общем ядре + UI-секция «Каналы чата» + генерация кода.
3. **Входящий поток**: групповые `message`/`message_created` → запись в `group_messages` (мэппинг автора, дедуп) → realtime в JTD.
4. **Исходящий fan-out**: `send-chat-telegram`/MAX-аналог переводим с per-user DM на «в группу, кроме источника»; персональные уведомления остаются в личке.
5. **ChatOps в группе**: контекст проекта по группе → AI-создание/команды без имени проекта, карточки задач в чат.
6. **TG на общее ядро**: постепенный перенос групповой логики TG-вебхука на `messenger-core` (приватный 1:1 не ломаем).

## Технические детали
- TG: групповые `chat.id` отрицательные; `allowed_updates` уже включает нужное; Privacy Mode off для полного зеркала.
- MAX: отправка через `sendMaxMessage(chat_id группы)`; подтвердить групповые `message_created`.
- Реюз: `messenger-core.ts` (транспорты TG/MAX, `aiBulkParse`, `createBulkTasks`, `handleCorePayload`), `messenger_list_context` для нумерации `/done N` (по `external_id` = id группы).
- Дедупликация входящих по `(source, external_message_id)`, чтобы ретраи вебхука не двоили.

## Решения для подтверждения
1. **Глубина зеркала:** мирроринг ВСЕХ сообщений группы в JTD (живой общий чат, но болтливые группы «зашумят» JTD) — или только сообщения, адресованные боту/реплаи (тише, но не «единый чат»). Рекомендую: всё мирроринг (это и есть единый чат), с возможностью отключить мирроринг на проекте.
2. **Несопоставленные авторы:** показывать их сообщения в JTD как `Имя (TG)` (рекомендую) или скрывать до привязки аккаунта.
3. **Личные уведомления:** оставляем в личке бота параллельно групповому чату (рекомендую).
