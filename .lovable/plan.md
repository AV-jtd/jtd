# План: CRM-чат поверх существующего чата проекта

Принцип — **аддитивно**: не создаём новый модуль и не переписываем чат. Боевой `ProjectChat` остаётся ядром, CRM-функции включаются только когда у проекта задан клиент.

## 1. Действия и system-карточки (расширяемый реестр)

Сейчас system-карточка одна (`task_created`), захардкожена в `systemMessages.ts`. Переводим на **единый реестр типов**, чтобы новые карточки добавлялись в одном месте и автоматически работали во всех чатах (чат проекта, чат задачи/комментарии, зеркала в Telegram/MAX, превью в мессенджере).

Типы карточек в первой версии:
- `task_created` — создана задача (есть сейчас)
- `assignment_created` — поручение (делегирование 1 уровня)
- `protocol_linked` — протокол/встреча привязан к чату
- (задел) `metric_logged` — зафиксирован показатель

Действия из сообщения (hover-меню + слэш-команды в композере):
- `/задача` → форма задачи (ответственный + дедлайн) → постит карточку `task_created`
- `/поручение` → делегирование → карточка `assignment_created`

**Ключевое требование:** один источник правды для карточек. Любой новый тип, добавленный в реестр, сразу:
рендерится в ленте, корректно показывается в превью списка чатов, и зеркалится в TG/MAX единым форматом маркера.

## 2. Полноэкранный режим + прямая ссылка

- Кнопка «развернуть» в шапке чата → полноэкранный режим (вместо узкой панели справа).
- Прямой URL вида `/chat/:groupId` — открывает конкретный чат сразу на весь экран (шарится ссылкой, работает из уведомлений/мессенджера).
- В полноэкранном режиме — трёхпанельный лейаут как в макете: список чатов слева (опц.), переписка по центру, контекст-сайдбар справа.

## 3. Привязка клиента + саммари в правом сайдбаре

- Новое nullable-поле `task_groups.client_id → clients`. Нет клиента — чат обычный, сайдбар скрыт.
- Привязка/отвязка клиента — в настройках проекта (пикер клиента).
- Когда клиент задан, в полноэкранном режиме справа — **саммари по клиенту**: карточка клиента (ранг A/B/C, стадия воронки), команда по клиенту (`task_participants` / `client_assignments`), ключевые задачи и поручения, плитки показателей. Всё read-only из существующих данных CRM.

## Что ещё предлагаю (ответ на «что ещё?»)

1. **Привязка протокола/встречи к чату** — кнопка «привязать протокол», карточка `protocol_linked` в ленте (используем `source_protocol_id`). Замыкает цепочку протокол → обсуждение → задача в одном окне.
2. **Непрочитанные и навигация** — бейдж клиента (эмодзи/ранг) у треда в unified messenger; счётчик непрочитанных уже есть, переиспользуем.
3. **AI-саммари переписки** — кнопка «свернуть обсуждение в итог» в сайдбаре (по аналогии с protocol summary), на потом.
4. **Мобайл** — полноэкранный режим = single-pane c переключением список ↔ чат ↔ контекст-дровер (как в макете `/dev/crm-chat`).

## Этапность

```text
Этап 1  Реестр system-карточек: вынести типы в один модуль,
        перевести task_created, добавить assignment_created.
Этап 2  Слэш-команды /задача /поручение в композере + hover-действия.
Этап 3  Полноэкранный режим + маршрут /chat/:groupId.
Этап 4  Миграция task_groups.client_id + пикер в настройках проекта.
Этап 5  Контекст-сайдбар клиента (саммари) в полноэкранном режиме.
Этап 6  Привязка протокола (protocol_linked) + бейджи в мессенджере.
```

Каждый этап самостоятелен, ничего не ломает: старые запросы игнорируют новое nullable-поле, чат-движок и realtime переиспользуются как есть.

## Технические детали

- **Реестр карточек:** расширить `src/lib/systemMessages.ts` — заменить хардкод на словарь `{ event → { icon, render(entityId, text), preview() } }`. Маркер остаётся `__sys_<event>__:<id>|<text>`, парсер уже generic. `formatMessagePreview` берёт из реестра. Зеркала TG/MAX (`messenger-core.ts`, `send-chat-telegram`) форматируют по тому же реестру.
- **Действия:** переиспользуем `useTaskMutations.addTask` и делегирование (`delegated_from`, `task_participants`); карточка пишется в `group_messages` тем же `external_message_id = "task-created:<id>"`-паттерном.
- **Fullscreen:** новый роут в `App.tsx` → страница-обёртка над `ProjectChat` (проп `fullscreen`); кнопка разворота переключает панель ↔ роут.
- **Миграция:** `ALTER TABLE task_groups ADD COLUMN client_id uuid REFERENCES clients(id)` (nullable) + индекс. RLS не трогаем — доступ к чату уже по членству в проекте; клиент только читается.
- **Сайдбар:** новый компонент `ClientContextPanel`, данные из `clients`, `client_assignments`, `useGroupTaskStats`, CRM `CRM_STAGES`. Рендерится только при `client_id`.
- **Реалтайм/перф:** без изменений — `useGroupChat` + channelManager LRU.

После согласования начну с Этапа 1 (реестр карточек) и Этапа 4 (поле `client_id`).
