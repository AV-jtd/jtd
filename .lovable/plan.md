# Комната клиента «в эфире»

Превращаем CRM-комнату клиента (на примере ФС, работает для всех клиентов) в живое рабочее пространство: к клиенту можно привязывать **протоколы, проекты/подпроекты и задачи**, а участники видят задачи и подзадачи, обновляющиеся в реальном времени, плюс ленту активности.

## Что уже есть (фундамент)
- Комната клиента `ClientRoomCenter` со вкладками Чат / Задачи / Метрики / Назначения.
- Привязка отдельных задач (`BulkLinkTasksDialog`) через `tasks.client_id`.
- Подтягивание задач из протоколов, помеченных клиентом (`protocol_meta.client_id`).
- Глобальный realtime-синглтон (`useRealtimeSubscriptions`) на tasks/subtasks с дебаунсом.

## Этап 1. Единая привязка к клиенту (протоколы + проекты + задачи)

Расширяем диалог привязки до трёх вкладок: **Задачи · Проекты · Протоколы**.

- **Задачи** — как сейчас (`tasks.client_id`).
- **Проекты/подпроекты** — выбор проекта проставляет `task_groups.client_id = clientId`. Привязка целого проекта подтягивает в комнату все его задачи и задачи его подпроектов (рекурсивно), без штамповки каждой задачи отдельно.
- **Протоколы** — выбор протокола проставляет клиента в `protocol_meta.client_id` (как делает шапка протокола), его задачи попадают в комнату.

Чтобы привязанные проекты реально отображались, `useClientTasks` в комнате будет собирать задачи из трёх источников: `tasks.client_id = clientId`, задачи протоколов с `protocol_meta.client_id`, и задачи проектов (и их подпроектов), у которых `task_groups.client_id = clientId`.

В комнате задачи группируются по источнику: «Прямые задачи», «Проект …», «Протокол …», с разворачиванием подзадач inline (используется существующий `TaskItem`).

## Этап 2. «В эфире» — realtime + лента активности

**Авто-обновление списка.** Расширяем глобальный синглтон: при изменениях в `tasks` / `subtasks` / `task_groups` дополнительно инвалидируются ключи комнаты (`client_room_tasks`, `client_task_threads`, `client_room_info`). Список задач и подзадач в открытой комнате обновляется без перезагрузки.

**Новая вкладка «Эфир»** — лента событий по клиенту, собираемая из уже имеющихся данных (без новой таблицы на первом шаге):
- создано / выполнено / перенесён срок (по `created_at`, `completed_at`, `deadline` + drift),
- новые комментарии и сообщения,
- кто и когда (аватар + имя из profiles),
сортировка по времени, авто-обновление через тот же realtime-инвалидатор.

## Этап 3 (отдельно, по согласованию). Кто видит комнату и задачи

Вы выбрали: видят **команда клиента** (`client_team`) и **участники привязанных задач**.

Важно: сейчас все внутренние пользователи видят все задачи (широкая RLS-политика `Consultant restriction on tasks`, которая для не-консультанта всегда истинна). Чтобы ограничить просмотр кругом команды, нужно поменять модель доступа **всего приложения**, а не только ФС, и это может скрыть данные у тех, кто их сейчас видит.

Поэтому предлагаю на этом этапе:
- Участники привязанных задач уже видят их (через `is_task_visible`: owner/assignee/participant/группа/отдел) — отдельных изменений не требуется.
- Доступ «только команда клиента» вынести в осознанное решение: либо включаем строгий режим глобально (рискованно, нужен аудит, кого это затронет), либо ограничиваем только новые/специально помеченные клиентские проекты. Конкретику согласуем перед изменением RLS.

То есть Этапы 1–2 делаем сейчас, по Этапу 3 сначала договариваемся о модели доступа.
