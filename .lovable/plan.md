# Единые карточки и воркфлоу задач в комнате клиента

## Проблема
В комнате клиента (`ClientRoomCenter.tsx`) вкладки «Задачи» и «Поручения» рисуют собственные карточки‑кнопки, которые по клику уводят из чата в общий список «Все задачи» (`onNavigateToTask`). Из‑за этого:
- дублируется верстка карточки задачи;
- теряется воркфлоу «Закрыть задачу / Создать связанную» (он есть только в `TaskItem` → `TaskChat`);
- выбор задачи переключает весь экран, а не раскрывает её на месте.

## Принцип решения
Один источник правды — компонент `TaskItem`. Он уже умеет: раскрываться inline, содержит `TaskChat` с кнопками «Закрыть задачу» и «Создать связанную» (`follow_up_of`), рисует системные карточки связей. Никаких новых сущностей и карточек — только переиспользование.

## Изменения (всё в `src/components/chat/ClientRoomCenter.tsx`)

### 1. Источник задач — полноценные Task-объекты
Заменить упрощённый `useClientRoomData` (там урезанный `RoomTask`) на получение настоящих `Task` через `useTasks()` с фильтром `task.client_id === clientId` (тот же паттерн, что в `ProjectDetailPanel`). Метрики/счётчики считать из этого же массива. Это даёт корректную форму для `TaskItem` (subtasks, task_tags и т.д.).

### 2. Вкладка «Задачи» — рендер через TaskItem
- Вместо кастомных `<button>`‑карточек рендерить `<TaskItem task={task} />` (активные сверху, завершённые — сворачиваемый блок, как в `ProjectDetailPanel`).
- Клик по задаче раскрывает её прямо в списке (встроенное поведение `TaskItem`), без ухода из чата.
- Внутри уже доступны «Закрыть задачу» и «Создать связанную задачу».

### 3. Вкладка «Поручения» — тот же TaskItem
Делегированный поднабор (`delegated_from`) рисовать тем же `TaskItem`, чтобы не было третьей версии карточки.

### 4. Шапка чата — кнопка «Открыть связанную задачу»
- Найти основную задачу клиента — CRM‑задачу воронки (`tasks` где `client_id = clientId` и `task_groups.project_type='crm'`; для «АЗС Лукойл» это единственная задача `АЗС Лукойл`).
- Добавить в правый блок шапки кнопку (иконка `ListChecks`/`SquareArrowOutUpRight`, title «Открыть связанную задачу»).
- По клику: переключиться на вкладку «Задачи» и авто‑раскрыть эту задачу inline (через `initialOpen`/ключ выбранной задачи), а не уходить из чата.
- Если связанной CRM‑задачи нет — кнопку не показывать.

### 5. Поведение onNavigateToTask
Оставить `onNavigateToTask` только как запасной путь (например, переход в полноэкранный общий вид по явному действию). По умолчанию выбор/открытие задачи происходит inline в комнате.

## Технические детали
- `useTasks()` уже загружен в приложении; фильтрация по `client_id` — как в `ProjectDetailPanel` (`useTasks` + filter), без новых глобальных запросов.
- «Связанная задача» определяется запросом: `tasks` join `task_groups` где `project_type='crm'` и `client_id=clientId`, `limit 1` (последняя по `created_at`). Кэшировать через `useQuery(["client_funnel_task", clientId])`.
- Авто‑раскрытие: хранить `expandedTaskId` в состоянии; для целевой задачи передавать `initialOpen` (как делает существующий механизм открытия задачи в `TaskList`).
- Завершённые задачи — сворачиваемый раздел (паттерн `ProjectDetailPanel`).
- Удалить неиспользуемый код упрощённых карточек и лишние поля `RoomTask`, если они больше не нужны.

## Проверка
- В комнате «АЗС Лукойл»: вкладка «Задачи» показывает реальные карточки; клик раскрывает inline; видны «Закрыть» и «Создать связанную»; экран не переключается на «Все задачи».
- В шапке появляется «Открыть связанную задачу» → открывает задачу воронки inline.
- Сборка проходит, рантайм‑ошибок нет.
