## Идея

Один чат-движок (`group_messages`), три уровня (scope). Новый модуль не строим — дорабатываем `ProjectChat`.

```text
Чат задачи     →  task_comments (по task_id)         — есть, не трогаем
Чат проекта    →  task_group без client_id           — есть (ProjectChat)
CRM-комната    →  task_group c client_id             — доработка
```

**CRM-комната клиента** — это запись `task_groups` со своим `project_type = 'crm_client'` и заданным `client_id`. Отдельная рабочая комната на клиента (1 клиент = 1 комната). Помечена особым типом, поэтому **не попадает** в обычный список проектов, PMO-портфель, NPD-матрицу — живёт только в чат-списке и CRM.

## Что делаем

### 1. Тип комнаты + авто-создание
- Используем уже добавленное поле `task_groups.client_id`. Добавляем `project_type = 'crm_client'` для комнат клиента.
- Комната создаётся лениво: при первом открытии CRM-чата клиента (из карточки клиента / списка комнат) — если у клиента ещё нет комнаты, создаём `task_group` (имя = имя клиента, `project_type='crm_client'`, `client_id`).
- Фильтруем `crm_client`-группы из обычных списков проектов/PMO/NPD.

### 2. Полноэкранный режим + маршрут
- Роут `/chat/:groupId` → страница-обёртка `ChatFullscreenPage`.
- Кнопка «развернуть» (уже есть в шапке) ведёт на этот роут; «свернуть» — назад в боковую панель.
- Трёхпанельный лейаут (на мобайле — single-pane с переключением).

### 3. Список комнат слева
- Левая панель = все комнаты: проекты + CRM-комнаты клиентов вперемешку.
- У каждой строки: иконка/эмодзи (для клиента — `ClientAvatar` + бейдж ранга A/B/C), последнее сообщение, непрочитанные (переиспользуем `useUnreadMessages`).
- Клик → центр открывает переписку этой комнаты.

### 4. Центр — переписка
- Тот же `ProjectChat` (system-карточки из реестра `chatCards.ts`, `/задача`, hover-действия). Без изменений логики.

### 5. Правый сайдбар — контекст клиента
- Новый `ClientContextPanel`, рендерится только если у комнаты задан `client_id`.
- Карточка клиента (ранг, стадия воронки CRM_STAGES), команда по клиенту (`client_assignments`), ключевые задачи, плитки показателей. Всё read-only из существующих данных CRM.
- Если `client_id` нет (обычный проект) — сайдбар скрыт или показывает базовую сводку проекта.

### 6. Привязка протокола (задел)
- Кнопка «привязать протокол» → карточка `protocol_linked` (тип уже в реестре), через `source_protocol_id`.

## Технические детали

- **Миграция:** комнаты различаем по `project_type='crm_client'` (поле `project_type` уже есть у `task_groups`). Доп. схема не нужна сверх `client_id`. Авто-создание комнаты — через `INSERT` в коде (insert-инструмент / клиент), не миграцией.
- **Фильтрация:** во всех запросах списков проектов/PMO/NPD добавить `.neq('project_type','crm_client')` (или исключение там, где уже фильтруется по типу).
- **Fullscreen-страница:** `src/pages/ChatFullscreen.tsx`, читает `:groupId`, рендерит 3 панели; центр = `ProjectChat` с `fullscreen`-режимом.
- **Список комнат:** новый `ChatRoomsList` (проекты с чатом + crm_client-комнаты), переиспользует `useUnreadMessages`, `useMessenger`.
- **Сайдбар:** `ClientContextPanel`, источники — `clients`, `client_assignments`, `useGroupTaskStats`, `CRM_STAGES`.
- **Реалтайм/перф:** без изменений — `useGroupChat` + channelManager LRU.

## Этапность

```text
Этап A  Тип crm_client + авто-создание комнаты клиента + фильтрация из списков.
Этап B  Роут /chat/:groupId + страница-обёртка + 3 панели (десктоп) / single-pane (мобайл).
Этап C  Список комнат слева (проекты + клиенты, бейджи ранга, непрочитанные).
Этап D  ClientContextPanel справа (read-only сводка клиента).
Этап E  Привязка протокола (protocol_linked) + вход в CRM-комнату из карточки клиента.
```

Каждый этап самостоятелен и ничего не ломает: `crm_client`-группы исключены из старых списков, чат-движок и realtime переиспользуются как есть.
