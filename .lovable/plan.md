# Доработки СТМ Mission Control

Четыре доработки. Схему БД менять не нужно — всё делается на существующих полях (`task_groups.stm_meta` JSONB, `task_participants`, `tasks`).

## 1. Остановить тайминг у SKU в «Архиве»

У архивных SKU время «зависания» и просрочка сейчас продолжают расти от текущей даты. Заморозим их на дате архивации (`archivedAt`).

- `stmTimeInStage()` — вместо `Date.now()` использовать `archivedAt`, если SKU в архиве.
- `isStmProjectOverdue()` — для архивных SKU считать просрочку по состоянию на дату архивации (этап, не закрытый к моменту архивации и с дедлайном раньше неё), а не по «сейчас». Практически это перестанет «докручивать» просрочку после сдачи в архив.
- В строке (`StmMatrixRow`) и раскрытой панели (`StmExpandedRow`) индикаторы «⏳ N дн» / «просрочено» у архивных больше не будут расти.

## 2. Редактирование и объединение «шапки» структуры (Сеть/Бренд/Проект/Дроп)

Заголовки групп в матрице формируются из `stm_meta`. Добавим их редактирование с каскадом на все SKU внутри группы.

- На строке-заголовке группы (и подгруппы «по проектам») появится кнопка-карандаш → диалог редактирования.
- В диалоге — поле «Название» текущего измерения (то, по которому идёт группировка: `retailer`/`brand`/`drop`, либо `project` для подгруппы).
- При сохранении — массовое обновление `stm_meta.<поле>` во всех SKU этой группы.
- **Объединение = переименование**: если ввести имя уже существующей группы, SKU автоматически сольются в неё (дубли Бренд/Проект/Дроп исчезнут). В диалоге покажем подсказку «Такая группа уже есть → SKU будут объединены» и количество затронутых SKU.

## 3. Участники и ответственный в «шапке» структуры (каскад на все SKU)

В том же диалоге редактирования группы добавим управление людьми, применяемое ко всем SKU группы:

- **Ответственный менеджер** (один) — через `AssigneePicker` + `useAvailableUsers`. Проставляется в `stm_meta.manager_id` всем SKU группы.
- **Участники** (мультивыбор, в т.ч. отдел/подрядчик) — через `MultiAssigneePicker`. Добавляются как записи в `task_participants` (role `support`) на все этапы-задачи каждого SKU группы, без дублей.
- Действие аддитивное (добавляет участников), с тостом «Добавлено N человек к M SKU».

## 4. Баг: при загрузке через Excel не грузится «Проект»

Причина найдена: поле `project` вообще отсутствует в маппинге импорта (`StmExcelImportDialog`), поэтому колонку «Проект» нельзя сопоставить, и значение теряется.

- Добавить `project` в список полей маппинга (`META_FIELDS` и опции селекта — «Проект»).
- В сборке превью SKU (`previewSkus`) заполнять `meta.project` из сопоставленной колонки.
- Обновить AI-маппинг колонок (edge-функция `ai-assistant`, action `map_stm_columns`), чтобы ИИ распознавал колонку «Проект» и складывал её в `project`.

## Технические детали

- **Новые хуки** в `useStmProjects.tsx`:
  - `useUpdateStmGroupMeta()` — принимает `{ groupIds, field, value }`, обновляет `stm_meta[field]` (читает текущий meta из кэша, патчит, пишет `task_groups.update`). Инвалидация STM-кэшей.
  - `useSetStmGroupManager()` — `{ groupIds, managerId }` → `stm_meta.manager_id`.
  - `useAddStmGroupParticipants()` — `{ groupIds, userIds }` → выбирает все `tasks` с `task_type='stm_stage'` этих групп, вставляет в `task_participants` (dedup по существующим).
- **Новый компонент** `StmEditGroupDialog.tsx` — объединяет п.2 и п.3 (название + менеджер + участники). Открывается из заголовка группы/подгруппы в `StmMatrixView`.
- **Правки функций** в `stmAnalytics.ts` — п.1 (заморозка на `archivedAt`).
- **Правки** `StmExcelImportDialog.tsx` — п.4 (поле `project`).
- **Правка** `supabase/functions/ai-assistant/index.ts` — п.4 (AI знает про «Проект») + редеплой функции.
- Все изменения данных идут через клиентские мутации (UPDATE/INSERT), **миграции БД не требуются**.
