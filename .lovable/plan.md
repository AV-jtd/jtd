## MAX мессенджер — альтернативный канал (не замена Telegram)

**Главный принцип:** Telegram остаётся основным каналом и продолжает работать как есть. MAX добавляется как **второй параллельный канал**. Каждый сотрудник может привязать оба, один или ни одного. Killer-фича — единый поток сообщений «Telegram ↔ MAX ↔ веб JTD».

API MAX (`platform-api.max.ru`) почти зеркалит Telegram: бот с токеном, webhook, отправка сообщений, inline-кнопки, проверка номера через контакт. MAX **нет** в коннекторах Lovable → работаем напрямую с токеном бота (как уже сделано для Telegram), без gateway.

---

### Этап 1. Фундамент: данные и привязка аккаунта MAX (MVP-основа)

Цель — пользователь может привязать аккаунт MAX и получать туда уведомления.

- Миграция БД:
  - `profiles.max_user_id` (bigint) + `profiles.max_chat_id` (bigint), уникальные индексы по аналогии с `telegram_chat_id`.
  - В `notification_preferences` — `max_*` флаги, зеркало существующих `telegram_*` (включая `max_group_chat_message`).
  - Значение `'max'` для поля `group_messages.source` (поле уже есть).
- Секрет `MAX_BOT_TOKEN` (вы создаёте бота в MAX, я запрашиваю секрет).
- Edge-функция `max-webhook` (минимальная): принимает события, реализует deep-link-привязку `?start=link_<userId>` (как у Telegram), сохраняет `max_chat_id`/`max_user_id` в профиль.
- Настройки → раздел «MAX»: кнопка «Привязать аккаунт MAX» + переключатели уведомлений (копия блока Telegram).

Результат этапа: уведомления JTD могут уходить и в Telegram, и в MAX.

---

### Этап 2. Рефактор: messenger-agnostic ядро (ключевой технический шаг)

`telegram-webhook` — ~3440 строк с большим набором команд (задачи, проекты, протоколы, чат, ИИ). Чтобы не копировать всё это в MAX, выделяем общий слой:

```text
                ┌─────────────────────────────┐
   Telegram ──► │  transport-adapter (TG)      │ ─┐
                └─────────────────────────────┘  │
                                                  ├─► messenger-core
                ┌─────────────────────────────┐  │   (команды, парсинг,
   MAX ───────► │  transport-adapter (MAX)     │ ─┘    ИИ-обогащение,
                └─────────────────────────────┘        работа с БД)
```

- `_shared/messenger-core.ts` — разбор команд, ИИ-обогащение, CRUD задач/чата (без специфики транспорта).
- Транспорт-адаптеры приводят входящее событие к единому формату и реализуют `sendMessage`/`sendKeyboard` под свой API.
- `telegram-webhook` переключается на ядро (поведение не меняется — регресс-проверка обязательна).

Результат этапа: один набор бизнес-логики для обоих мессенджеров.

---

### Этап 3. Бот MAX: постановка задач и команды

- `max-webhook` подключается к `messenger-core` через MAX-адаптер.
- Базовый набор команд (как у Telegram): создать задачу, список задач, выполнить, назначить ответственного, выбрать проект, ИИ-ассистент.
- Регистрация webhook (`POST /subscriptions`, HTTPS — у вас уже есть `justtodoit.ru` + certbot) и меню команд бота.

Результат этапа: сотрудник ставит задачи из MAX так же, как сейчас из Telegram.

---

### Этап 4. Единый поток чата TG ↔ MAX ↔ JTD (killer-фича)

- Fan-out хелпер `_shared/chat-fanout.ts`: при новом сообщении в `group_messages` рассылает копию во все привязанные каналы участников (Telegram + MAX), кроме автора.
- Рефактор `send-chat-telegram` + новая `send-chat-max` под общий fan-out.
- Подавление эха: сообщение из MAX не возвращается в MAX (по `sender_user_id` / `source`, паттерн уже есть).
- Привязка чатов проектов к MAX-группам (команда `/link`, как в Telegram).

Результат этапа: единый поток — кто-то пишет из Telegram, кто-то из MAX, кто-то из веба, все видят всё.

---

### Технические детали и риски

- **Webhook только HTTPS** + сертификат доверенного УЦ (самоподписанные MAX запретил) — `justtodoit.ru`/certbot подходит.
- **Лимит 30 rps** на `platform-api.max.ru` → закладываем ретраи/очередь при массовых рассылках.
- **Антидубли**: идемпотентность по id события + подавление эха при fan-out.
- **Зрелость API**: MAX моложе Telegram, возможны изменения — изолируем в адаптере.
- **Авторизация**: `request_contact` + HMAC-SHA256 можно использовать как 2FA-альтернативу (опционально, отдельно).
- Telegram-флоу не трогаем по поведению — только переводим на общее ядро с регресс-тестом.

### Объём
- Этап 1 — небольшой (миграция + привязка + настройки).
- Этап 2 — средний/крупный (рефактор ядра, главный риск регресса).
- Этапы 3–4 — средние (переиспользуют ядро и fan-out).

Можно начать с Этапа 1 (привязка MAX + уведомления) как быстрый MVP, а ядро/бот/единый чат катить дальше.
