## Связь чатов задач с клиентом

### Источник связи — без новых сущностей
Используем уже существующее поле **`tasks.client_id`** как единственный источник правды «чат задачи принадлежит клиенту». Чат задачи живёт в `task_comments` (как сейчас) — мы НЕ переносим сообщения и НЕ дублируем их в `group_messages`. «Подвязан» = у задачи проставлен `client_id`. Это:
- не плодит таблиц (отдельная связь client_linked_chats не нужна — M:N тут избыточен, задача всегда про одного клиента);
- уже совместимо с CRM-карточкой, риск-радаром и `TaskClientPicker`.

```text
clients ──< tasks (client_id) ──< task_comments
   │                                  (чат задачи, как есть)
   └── task_groups (crm_client room) ──< group_messages
        (лента комнаты клиента)
```

## Два входа привязки (симметрично)

1. **Из чата задачи** — в шапке/меню чата задачи кнопка «Привязать к клиенту» (переиспользуем `TaskClientPicker`: поиск + inline-создание + «Отвязать»). Уже есть иконка 🏢 в `TaskItem` — добавляем тот же пикер в шапку чата задачи.
2. **Из комнаты клиента** — в комнате клиента кнопка «＋ Чат задачи»: выбрать существующую задачу клиента или создать новую (задача создаётся сразу с `client_id`). Привязка существующей = проставить `client_id`.

Обе точки пишут одно поле `tasks.client_id` → состояние всегда консистентно, отвязка работает из любого места.

## Эргономика просмотра — «и единая лента, и отдельный чат»

Главное решение: **НЕ вливать сотни комментариев задач в ленту клиента построчно**. Вместо этого — единая хронологическая лента комнаты клиента, где чат каждой задачи представлен **сворачиваемой карточкой-веткой**, вставленной по времени последнего сообщения:

```text
┌─ Лента комнаты «Лукойл» ───────────────────────────┐
│  • сообщение команды (group_messages)              │
│  ┌── 📋 Задача «КП на дизель» · 4 сообщения  ▸ ──┐ │  ← свёрнуто
│  │  последнее: «Иван: отправил, ждём» · 2ч       │ │
│  └────────────────────────────────────────────── ┘ │
│  • сообщение команды                                │
│  ┌── 📋 Задача «Образцы» · 12 сообщений  ▾ ─────┐  │  ← развёрнуто inline
│  │  Аня: согласовали объём                       │  │
│  │  Иван: отгрузим в пятницу                      │  │
│  │  [ Открыть чат задачи → ]                      │  │
│  └────────────────────────────────────────────── ┘ │
└─────────────────────────────────────────────────────┘
```

Поведение:
- **Свёрнуто** (по умолчанию): карточка ветки = иконка 📋 + название задачи + счётчик сообщений + бейдж непрочитанных + превью последнего сообщения с автором/временем.
- **Развернуть** (клик по шапке карточки): inline-подгрузка последних N (≈10) сообщений `task_comments` прямо в ленте — быстрый просмотр без ухода.
- **«Открыть чат задачи →»**: переход в полноценный чат задачи (отдельный, как сейчас), где доступны все возможности (вложения, упоминания, история целиком).
- Каждое раскрытое сообщение помечается источником (название задачи), чтобы было видно, «откуда» оно — выполняет твой запрос про «из какой задачи комментарий».

Это даёт оба режима одновременно: целостная картина по клиенту в одной ленте + полноценный отдельный чат задачи по клику, без перегруза.

## Объём работ

**Данные**
- Без миграций. Только чтение `tasks.client_id` + агрегаты по `task_comments`.

**Хук `useClientTaskThreads(clientId)`**
- Список задач клиента (`tasks.client_id = clientId`) с: последним сообщением, счётчиком, непрочитанными (через существующий `chat_read_status`).
- Ленивая подгрузка последних сообщений задачи при разворачивании.

**Комната клиента (`ClientRoomCenter` / лента)**
- Вставка карточек-веток в общий timeline по времени последнего сообщения.
- Компонент `ClientTaskThreadCard` (свёрнуто/развёрнуто, кнопка «Открыть чат задачи»).
- Кнопка «＋ Чат задачи» в шапке/композере комнаты (выбор/создание задачи клиента).

**Чат задачи**
- Кнопка «Привязать к клиенту» (`TaskClientPicker`) в шапке чата задачи + бейдж текущего клиента со ссылкой в комнату клиента.

**Память**
- Обновить `streams/crm-client-card.md` и `features/crm/task-client-link.md`: модель «task chat ↔ client через client_id», эргономика коллапс-веток.

## Технические детали
- Реюз: `TaskClientPicker`, `chat_read_status` (непрочитанные), `channelManager` (realtime на раскрытой ветке), паттерн system-карточек из `chatCards.ts`.
- Производительность: карточки веток не тянут все комментарии — только агрегаты; полные сообщения только при разворачивании (ленивый `useQuery` на ветку).
- RLS не трогаем: доступ к `task_comments` уже регулируется существующими политиками задачи.
