# Задача → Клиент (быстрая привязка)

## Решение архитектуры
- **Клиент — отдельная сущность, не тэг.** Тэги остаются для свободной категоризации, клиент — бизнес-объект (контакт, город, ранг, логотип). Дедуп через `upsert_client_by_name` + unique-индекс на `lower(name)`.
- Параллельные стримы: `tasks.client_id` (CRM-привязка) ⊥ `tasks.tags` (метки) ⊥ `tasks.group_id` (проект).
- Задача из протокола наследует `client_id` из `task_groups.protocol_meta.client_id` (см. `protocol-partner-side`). Ручная привязка перезаписывает это.

## UI
- В быстрых иконках `TaskItem` слот ✨ ИИ заменён на 🏢 `Building2`.
- `TaskAiPopover` полностью убран из карточки (ИИ остаётся в глобальном AI Assistant).
- Компонент `src/components/TaskClientPicker.tsx`:
  - Поиск по `clients.name / contact_name / city`.
  - Inline-создание через RPC `upsert_client_by_name` если точного совпадения нет (от 2 символов).
  - Кнопка «Отвязать клиента» если уже привязан.
  - Подсветка trigger primary-цветом если `client_id` установлен.

## Эффект
- Клиент-привязанные задачи автоматически попадают в CRM-карточку клиента и риск-радар (через существующие связи).
- Любой пользователь может создать клиента из карточки задачи — общий справочник дедуплицируется на уровне БД.

## Telegram: смарт-привязка по контексту
- Хелпер `resolveClientIdFromContext(supabase, groupId, text)` в `telegram-webhook`. Приоритет:
  1. Контекст проекта — привязанный чат ведёт в client-room (`task_groups.client_id`) или его родитель (`parent_id`).
  2. Совпадение имени — известное имя клиента встречается дословно в тексте задачи (справочник `clients` глобальный, дедуп по `lower(name)`).
- Применяется во всех путях создания: `/task`, общий поток (личка/контекст), и `createBulkTasks` (`/spisok`). Подтверждение показывает `🏢 <Клиент>`.
