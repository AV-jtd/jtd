Шаблон протокола `cross_functional` — это внутренний регулярный ритуал команды (в отличие от `client_negotiation`/«переговоры», который служит базой). Доработки:

1. **Форма создания (NewProtocolDialog)**:
   - Скрыты партнёрские axes-чипы (required_axes/optional_axes) — для внутренней встречи это шум.
   - Описание не подставляется автоматически (для других шаблонов оставлено как было).
   - Блок «Подтянуть открытые поручения с прошлых встреч»: до 30 кандидатов, чекбоксами выбираем несколько прошлых протоколов. Клонируемые задачи создаются как `is_draft=true` И `protocol_scope='internal'` — чтобы сразу попадали в единственный видимый блок CF (см. п.3). На клонах сохраняется `source_protocol_id`. Авто-выбор НЕ применяется (встречи часто по разным темам).
   - **Фильтр «Серия встреч» по теме (event_topic)**: pill-чипы тем над списком, выведенные из `task_tags` (самая частая event_topic-тема per protocol). Выбор серии сохраняется в `localStorage["protocols:newDialog:topicFilter"]` — переживает закрытие диалога и переключение шагов. Если сохранённая тема исчезла из кандидатов, фильтр тихо сбрасывается на «Все».
   - В `protocol_meta` пишется `template_system_key` для идентификации.

2. **Soft-дисциплина (ProtocolDetailPage)**: для draft CF показывается мягкий баннер (primary, не блокирующий), если пустое описание ИЛИ нет ни одного internal-attendee (ни в meta, ни среди assignee задач).

3. **Минималистичная страница протокола (ProtocolDetailPage) — для CF убраны все партнёрские артефакты**:
   - Заменён `ProtocolHeader` (sides, форматы, CRM-привязка, axes-чипы, sides-картинки) на компактный inline-`CrossFunctionalHeader`: только название + дата + список участников (auto из assignee).
   - Скрыты `ProtocolSummary`, `ProtocolTableView` (партнёрская таблица со сторонами/осями) и `CrmReportPlaceholder`.
   - Кнопка «Превью» убрана из draft-баннера, `ProtocolPreviewDialog` не монтируется.
   - Единственный видимый блок — `ProtocolInternalSection` с `variant="cross_functional"`: нейтральный заголовок «Поручения по итогам встречи» (вместо красного «Внутренние задачи / не уходит партнёру»), primary-цвета вместо красных, секция и список открыты по умолчанию.

Поля «модератор/секретарь/чек-лист функций» НЕ добавляли — выбран был только carry-over из ключевых полей.
