# Внешние пользователи — единые правила доступа

## Правило
**Любой внешний пользователь** (подрядчик, партнёр, консультант, аудитор, фрилансер, представитель клиента и т.д.) по умолчанию получает права роли `consultant`:

- Видит **только** задачи, где он назначен/участник или которые делегированы на его компанию.
- Видит **только** себя, коллег по своей компании и людей из общих задач.
- Полностью скрыто: PMO, NPD, CRM, STM, Протоколы, Wiki, Сообщество, Команда, Дашборд, Архив, Мой отдел, Админка.
- Скрыты глобальные инструменты: поиск, AI-ассистент, Insights, мессенджер групп.
- Не видит структуру компании (отделы, другие команды, других подрядчиков).

## Как применять при разработке
1. **Новая категория внешних пользователей** → добавляется в существующую модель `consultant` (через `contractor_id` или новое поле с триггером, аналогичным `sync_consultant_role`). НЕ создавать параллельную роль с собственными правилами.
2. **Новая таблица с конфиденциальными данными** → сразу добавляется RESTRICTIVE-политика `Consultant block on <table>` или `Consultant restriction on <table>` через хелперы (`is_consultant`, `consultant_can_see_*`).
3. **Новый модуль/раздел/роут** → по умолчанию закрывается для consultant через `<ConsultantBlocked>` в `App.tsx` и фильтр в `MainNav`.
4. **Новый глобальный UI-элемент** (поиск, AI, мессенджер, дашборд и т.д.) → проверка `useAuth().isConsultant` и скрытие.
5. **Новая edge-функция, обходящая RLS через service role** → обязательная проверка `is_consultant(user_id)` в начале и блок/фильтрация выдачи.

## Расширение модели
Если появится новая категория с **другими** правилами (например, «партнёр-наблюдатель» с расширенным доступом), её нужно явно обсудить с пользователем перед реализацией. По умолчанию — consultant-правила.
