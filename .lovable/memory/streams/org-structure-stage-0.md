# Этап 0 — Оргструктура и роль director

Фундамент перед запуском воркфлоу «директор → начальник → PM → отдел → подрядчик → CRM-партнёр». Без этого этапа дальнейшие сценарии (триаж сирых задач, дашборд директора, SLA для подрядчиков) построить нельзя — сейчас 33 юзера лежат плоской свалкой.

## Контекст и боли

- **68% задач без ответственного** — никто не подбирает (главная боль)
- 33 пользователя, из них **6 уже распределены** по 6 отделам (Закупки, FS Маркетинг и др.) — остальные 27 нужно разложить
- Подрядчики и CRM-партнёры — только метка, мы сами трекаем (без приглашения в систему)
- 1 PM = 1 проект (NPD/STM/CRM)
- teams (команды) **не трогаем** в этом этапе — оставляем как есть

## Решения по архитектуре (приняты)

### 1. Иерархия отделов: древовидная (Вариант B)
- `departments.parent_department_id` (uuid, nullable, ON DELETE SET NULL)
- Head-of верхнего уровня видит все подотделы рекурсивно
- Теги площадок (КМ/ФЗ/АА) остаются ортогональными — фильтр через тег `site`

Пример для Закупок:
```
Закупки (head + director)
├─ Закупки сырья
├─ Закупки упаковки
└─ Закупка оборудования
```

### 2. Роль director: гибрид с ручным стартом
- Добавить `director` в enum `app_role`
- Новая таблица `department_directors (director_user_id, department_id)` — many-to-many
- Сейчас Артём раздаёт вручную через UI Оргструктуры
- Позже навесим триггер для авто-присвоения тем, у кого ≥2 подотделов
- Тестовый кейс: отдел «Закупки»

### 3. Миграция 33 юзеров: Bulk-экран
- Таблица всех юзеров с dropdown отделов и ролей
- Сохранение по строке или массово
- В Settings → новая вкладка «Оргструктура»

### 4. teams — не трогаем

## План работ (3 шага)

### 0.1 Миграция БД
- `departments.parent_department_id` (self-FK)
- enum `app_role` += `director`
- Таблица `department_directors`
- SECURITY DEFINER функции:
  - `is_director_of_department(_user_id, _department_id)` — прямой или через parent
  - `get_user_visible_departments(_user_id)` — свой отдел + подотделы (если head-of) + курируемые (если director)
- Обновить RLS task_groups/tasks: директор видит через новую функцию

### 0.2 UI: Settings → вкладка «Оргструктура»
- **Левая колонка**: дерево отделов (drag для смены parent, кнопка «+ Подотдел»)
- **Правая колонка** при выборе отдела:
  - Head-of (UserPicker)
  - Директора-кураторы (multi-UserPicker)
  - Сотрудники с drag-out
- **Bulk-блок**: таблица 33 юзеров, колонки: Имя | Email | Текущий отдел (dropdown) | Роль (user/head-of/director/manager)

### 0.3 Перенастройка `MyDepartment.tsx`
- Авто-определение роли:
  - `director` → табы по курируемым отделам
  - `head-of` → один отдел + все подотделы дерева
  - `user` → свой отдел и коллеги
- Использует `get_user_visible_departments`
