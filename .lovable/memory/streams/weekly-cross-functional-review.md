# Weekly Cross-Functional Review

## Контекст и боль

Сейчас раз в неделю собираются все функции (R&D, Маркетинг, Продажи, Производство КМ/ФЗ/ФС/АА, Качество, СТМ-менеджер) и:
- Смотрят протокол прошлой встречи и **обсуждают каждый вопрос с нуля**
- Между встречами статусы не обновляются в одном месте
- Никто не приходит с цифрами
- Решения прошлой недели не отслеживаются

**Бизнес-боль (из processes.md):** 68% задач без ответственного, 55% без дедлайна. Многие проекты вообще не заведены. Дисциплина заполнения низкая.

## Главный принцип ритуала

**«Нет в системе — нет на встрече»**

- Если проекта нет в JustTODOit — он не обсуждается
- Если задача без ответственного и дедлайна — она не считается «в работе»
- Если поручение прошлой встречи не закрыто и нет обновления статуса — публичный разбор

Ритуал = инструмент социального давления для выравнивания дисциплины. Через 3-4 встречи дисциплина должна выровняться, после чего можно вводить более сложные механики (DoD-чеклисты для гейтов и т.д.).

## Расписание ритуала

| День | Время | Событие |
|---|---|---|
| Пн 17:00 | Авто | Личная Telegram-рассылка каждому: «твои просроченные / без assignee / без deadline» |
| Вт 09:00 МСК | Авто | Генерация pre-read + публикация в Wiki + рассылка участникам |
| Вт ~11:00 | Встреча | 60 минут по сценарию |
| Вт 12:30 | Модератор | Финализация протокола, публикация → задачи разлетаются по проектам через теги осей |

## Структура pre-read «Cross-Functional Snapshot»

### Секция 0: 🚨 Дисциплина (САМОЕ ПЕРВОЕ)
- Сколько активных задач **без ответственного** (по отделам)
- Сколько **без дедлайна** (по отделам)
- Сколько проектов **не обновлялись >2 недель** (мёртвые души)
- **Топ-5 «нарушителей» поимённо** (решено: публично в pre-read)

### Секция 1: ✅ Поручения прошлой встречи
- Все задачи с `source_protocol_id = прошлый протокол`
- Статусы: ✅ закрыто / 🔄 в работе / ⚠️ просрочено / ❓ нет статуса
- Жирным — те, по кому исполнитель не дал обновления

### Секция 2: 📊 Портфель проектов (универсально)
**Решено:** ответственный за проект до встречи помечает «нужно обсудить» + автоматически попадают проекты с изменениями за неделю. Не висит лента из 50 проектов.

Табы:
- **NPD** — по гейтам G0→G5
- **CRM** — по этапу воронки
- **СТМ** — активные контракты
- **Прочее** — R&D / маркетинг / операционка

На каждый проект: прогресс, ответственный, deadline, drift.

### Секция 3: 🏭 По площадкам (КМ/ФЗ/ФС/АА)
Срез через системный тег `site`:
- Сколько активных проектов на каждой
- Загрузка ответственных
- Конфликты ресурсов

### Секция 4: 🔍 Срезы (раскрывающиеся аккордеоны)
- По брендам
- По клиентам (Пятёрочка/Магнит/...)
- По отделам (R&D/Маркетинг/Продажи)
- По запускам/проектам — топ-10 по риску от Risk Radar

### Секция 5: 📈 KPI-снимок недели
- Закрыто задач: N (vs прошлая неделя)
- Создано задач: M
- Просрочено: K
- Проектов сменили статус: P
- **% задач с полными метаданными (assignee + deadline)** — главная метрика дисциплины

## Сценарий встречи (60 мин)

| # | Блок | Время | Что |
|---|---|---|---|
| 1 | 🚨 Дисциплина | 5 мин | Модератор читает Секцию 0. Кто в красной зоне — отвечает прямо сейчас. |
| 2 | ✅ Чек-лист поручений | 10 мин | По Секции 1. Каждый: 30 сек на «закрыто / перенос на дату / нужна помощь». |
| 3 | 📊 Портфель: что движется/застряло | 20 мин | По табам NPD → CRM → СТМ → Прочее. Только проекты, отмеченные ответственным или со сменой статуса. |
| 4 | 🏭 Площадки + срезы | 10 мин | Узкие места, конфликты ресурсов |
| 5 | 🆕 Новые вопросы | 10 мин | Решения с фиксацией: assignee + deadline ОБЯЗАТЕЛЬНО, иначе вопрос откладывается |
| 6 | 🎯 Итог | 5 мин | Модератор зачитывает все новые поручения с экрана |

## Принуждение к дисциплине

**Решено:** на финализации протокола модератор сам решает.

Механика: при попытке опубликовать протокол — модальное окно «У тебя 3 строки без assignee и 2 без deadline. Опубликовать с пометкой "недоработка" или вернуться?». Это даёт гибкость + социальное давление + не блокирует встречу.

## Этапы реализации (последовательно)

| Этап | Что | Зачем | Размер |
|---|---|---|---|
| **0. Регламент** | Wiki-страница с правилами ритуала, ролями, форматом pre-read | Без правил — превратится в болтологию | S |
| **1. Дисциплина** | View «кто без assignee/deadline», Telegram-рассылка в Пн 17:00 | Главная боль | M |
| **2. Pre-read v1 ручной** | Wiki-страница, модератор собирает по чек-листу | Проверяем формат на 2-3 встречах | S |
| **3. Автогенерация pre-read** | Edge function по cron (Вт 09:00) → Wiki + Telegram | Снимаем нагрузку | L |
| **4. Чек-лист поручений в новом протоколе** | Кнопка «Подтянуть открытые с прошлой встречи» при создании cross-functional протокола | Решает «обсуждение с нуля» | M |
| **5. Soft-валидация полей в протоколе** | На публикации показываем «недоработки», модератор решает | Прививает дисциплину без полной блокировки | M |
| **6. KPI-снимки + тренды** | Таблица + блок в pre-read «Тренды за 4 встречи» | Видим, работает ли система | M |
| **7. NPD DoD-чек-листы** (отдельный стрим) | Definition of Done для каждого гейта | Когда дисциплина выровняется | L |

## Документы экосистемы

1. **Регламент ритуала** (Wiki-страница) — статичный, читают все участники
2. **Шаблон pre-read** (Wiki + автогенерация) — динамический, генерируется еженедельно
3. **Шаблон протокола `cross_functional`** (уже в `protocol_templates`) — расширить soft-валидацией assignee/deadline
4. **Дашборд «Дисциплина»** (новый view) — публичный, видно всем
5. **Таблица `meeting_kpi_snapshots`** (новая) — для трендов

## Связь с другими стримами

- **context-model** — pre-read и срезы используют 9 системных категорий тегов (site, brand, clients, department)
- **protocols-r7** — шаблон `cross_functional` базируется на инфраструктуре R7
- **dashboard-export** — переиспользуем форматы для PDF-экспорта pre-read
- **ai/daily-insights** — Risk Radar даёт топ-10 проектов по риску для Секции 4
- **processes.md** — этот ритуал = практический ответ на проблемы дисциплины из аналитики

## Решения, принятые в проектировании

1. ✅ **Старт ритуала** — вторник 09:00 МСК (а не четверг 18:00)
2. ✅ **Принуждение к assignee+deadline** — soft-валидация на публикации, решает модератор
3. ✅ **«Нарушители»** — поимённо в pre-read (жёстко, но работает)
4. ✅ **Отбор проектов для обсуждения** — ответственный сам помечает + авто по изменениям
5. ✅ **Универсальность** — ритуал НЕ только для NPD, охватывает весь портфель (NPD/CRM/СТМ/прочее)
6. ✅ **Подготовка** — модератор + AI-черновик
7. ⏳ **NPD DoD-чеклисты** — откладываются до этапа 7, когда дисциплина выровняется
