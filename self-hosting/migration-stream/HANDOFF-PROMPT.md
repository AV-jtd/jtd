# Промпт для передачи управления Claude Code на VPS

Скопируй весь блок ниже и вставь в Claude Code сразу после запуска `claude`
на сервере. Он содержит весь контекст — Claude сразу поймёт ситуацию и начнёт
вести работу по фазам.

---

## Промпт (копировать целиком)

```
Ты работаешь на VPS в рамках переезда приложения JTD (task-менеджер)
с облачного Supabase (AWS) на этот российский сервер. Тебе переданы
реальный контроль над сервером и SSH-сессия через Claude Code CLI.

Весь план и скрипты уже в репозитории. Начни так:

1. Прочитай файлы (именно в таком порядке):
   - /opt/jtd/self-hosting/migration-stream/README.md
   - /opt/jtd/self-hosting/migration-stream/PROGRESS.md  ← статус и реквизиты
   - Соответствующий PHASE-файл для текущей фазы

2. Определи где мы находимся по PROGRESS.md (какой пункт — первый незакрытый).

3. Выполни следующий шаг, используя скрипты из:
   /opt/jtd/self-hosting/migration-stream/scripts/

Правила работы:
- Перед КАЖДЫМ шагом — скажи что собираешься делать и жди подтверждения
  (если шаг необратимый или занимает >2 минут)
- Для рутинных проверок (preflight, health-check) — запускай сразу
- После каждого скрипта — покажи вывод и интерпретируй результат
- Если скрипт завершился с ошибкой — НЕ иди дальше, разберись с причиной
- ПЕРЕД переключением DNS (фаза 4, шаг 7) — обязательно стоп и подтверждение

Текущие реквизиты (заполни из PROGRESS.md или я скажу):
- Connection string облачной БД для дампа: сообщу отдельно
- S3-ключи: сообщу отдельно (не писать в файлы)

Начинай: прочитай PROGRESS.md и скажи в двух строках — где мы,
что следующий шаг.
```

---

## Инструкция по заполнению реквизитов

Секреты (пароли, ключи, connection strings) НЕ вставлять в промпт напрямую.
Claude спросит их отдельно — передай в чате, он использует их только
в текущей сессии и не коммитит в репозиторий.

---

## Как обновлять статус между сессиями

После завершения каждой фазы или шага — попроси Claude:
```
Отметь в PROGRESS.md пункты которые мы выполнили и запиши в журнал сессий.
Закоммить и запушь.
```

Так следующая сессия (или эта же после перерыва) видит актуальный статус.

## Про Lovable

Lovable продолжает работать для UI-изменений как раньше. После переезда
единственное отличие: VITE_SUPABASE_URL будет указывать на ваш VPS
вместо облачного Supabase. Claude Code управляет инфраструктурой,
Lovable — фронтендом. Они не конфликтуют.
