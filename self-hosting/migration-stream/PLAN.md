## Архитектура после переезда

```
Пользователь (РФ, без VPN)
        ↓ https://justtodoit.ru
   nginx на VPS (189.74.120.232)
        ├─ / → фронтенд (dist/)

                            ↓
              Supabase self-hosted стек
              (auth, rest, realtime, storage, edge)
                            ↓
                     PostgreSQL 15
```

Lovable продолжает разработку → пушит в GitHub → GitHub Actions
собирает и деплоит на VPS + применяет миграции (deploy-vps.yml).

## Принцип безопасности

- Облачный Lovable Supabase **не трогаем** — он остаётся рабочим до и после
  переезда как источник и standby.
- Откат до Шага 5 — мгновенный (DNS не переключён).
- После Шага 5 откат — возврат DNS на Lovable.

## Бэклог (после завершения миграции данных)

Отложенные задачи, зафиксированы чтобы не потерялись между сессиями:

1. **Финальная перезаливка данных** — свежий экспорт от 5 июля
   (`s3://jtd-backups/jtdbackup20260705.zip`, 67 таблиц, все колонки).
   TRUNCATE + reload против уже правильной схемы. Проверить заполнение
   profiles.display_name и др.
2. **Системный прогон** — пройти все фичи, собрать реальные (фатальные)
   ошибки, отделить от benign-шума (напр. 409 на tags в STM — известный шум).
3. **414 URI Too Long** — поднять large_client_header_buffers на внешнем
   nginx и Kong (KONG_NGINX_HTTP_LARGE_CLIENT_HEADER_BUFFERS).
4. **Realtime 403** — `/sb/realtime/v1/websocket` отдаёт 403, живые
   обновления не работают. Отдельная задача авторизации realtime.
5. **SMTP** — `SMTP_PASS=ЗАМЕНИТЬ_ПОЗЖЕ` плейсхолдер. Нужен реальный пароль
   noreply@justtodoit.ru (smtp.yandex.ru) для reset-password писем.
6. **Раздача паролей 54 пользователям** — временные пароли +
   флаг must_change_password.
7. **Авто-деплой** — активировать `deploy-vps.yml`: добавить секреты в GitHub
   (VPS_SSH_KEY, VPS_HOST, VPS_SUPABASE_URL, VPS_SUPABASE_ANON_KEY).
   Разблокирует цепочку Lovable → git → авто-деплой на VPS.
8. **Фича «дружелюбная смена пароля»** — строить в Lovable после авто-деплоя.
   UI-экран смены пароля (`supabase.auth.updateUser`) + гейт по флагу
   must_change_password. Схему БД не трогает.
9. **email_queue функции локализовать** — email_queue_dispatch/wake
   ссылаются на облачный URL Lovable + vault-секрет, на VPS не работают.
11. **Самохостинг шрифтов** — `fonts.googleapis.com` (Segoe UI и др.)
    блокируется из РФ, запрос падает (косметика — откат на системный шрифт).
    Скачать woff2, отдавать с nginx, убрать внешнюю зависимость.
12. **Проверить Google-зависимости на смоук-тесте** — FCM Push из РФ скорее
    всего не работает (риск в реестре), основной канал — Telegram.

10. **www.justtodoit.ru** — переключён вручную на VPS (было canChange:false
    через API). Проверить что резолвится, добавить 301 www → корень.

13. **AI через OpenRouter** — «ИИ временно недоступен»: на Lovable AI работал
    через их шлюз (LOVABLE_API_KEY), на VPS его нет. Привязать свой ключ
    OpenRouter: обновить AI edge-функции (endpoint + ключ в .env.supabase),
    убрать зависимость от Lovable AI Gateway. Запасной вариант для РФ —
    GigaChat/YandexGPT (в реестре рисков).

## Правило разработки на будущее

Любые изменения схемы БД — **только через миграции в git**, никогда через
ручной SQL-редактор Lovable. Иначе объект не попадёт в git и не доедет до VPS
(так и появилась проблема с таблицей `clients`). Данные живут только на VPS,
код течёт через git+авто-деплой.
